# Team Jape: short-form gameplay and posting guide

Team Jape is the developer account. Beyond the Belt is the current game. Use this guide for gameplay reveals, feature demonstrations, and development updates across Instagram, TikTok, YouTube Shorts, Facebook, and X/Twitter.

Platform guidance checked **27 September 2026**. Hashtag counts below are practical starting points, not promises of reach; platform limits and link access can change. The example tags are relevant suggestions, not verified trending tags.

## Quick platform reference

| Platform | Our video export | Description approach | Link call to action | Suggested hashtags |
| --- | --- | --- | --- | --- |
| Instagram Reels | Vertical 9:16 | Hook, a little context, one next step | “Link in bio” when the profile link is set | 3–5 relevant tags |
| TikTok | Vertical 9:16 | Short hook tied to the action on screen | “Link in bio” only if a working website link is available; otherwise “Follow for development updates” | 3–5 relevant tags |
| YouTube Shorts | Vertical 9:16 | Clear title; short description naming the game and feature | “Game page linked on our channel profile” | 2–3 in the description |
| Facebook Reels / Page | Vertical 9:16 for Reels | Explain the game for someone seeing it for the first time | Reels: Page website link; regular Page posts: direct URL where supported | 0–3 relevant tags |
| X/Twitter | Square 1:1 | One concise observation, feature, or development update | Direct URL in the post | 0–2 relevant tags |

These are our export preferences, not exclusive platform requirements. The shorts skill renders the vertical version; for a square X version, capture the same scenes at `"width": 2880, "height": 2880` and render an edit with `"size": [1080, 1080]`.

## Write the post around what the clip actually shows

Use **a concrete hook → the game or development context → one next step**. A gameplay post can explain the experience; a development post can explain what changed and why. Keep development claims accurate: do not call a feature new or improved unless it actually is.

- Use the game name in normal text as well as, optionally, a hashtag.
- Use player-facing tags such as `#IndieGame`, `#IncrementalGame`, or `#SpaceGame` for gameplay. Use `#GameDev`, `#IndieDev`, or `#GameDevelopment` when discussing the development process.
- `#BeyondTheBelt` identifies this game; `#TeamJape` can identify studio-wide posts. Neither needs to appear in every post.
- Prefer tags that describe the clip. Use `#PixelArt` for relevant visuals, `#MonoGame` for engine-focused posts, and `#ScreenshotSaturday` for an appropriate Saturday update. Do not use `#MadeWithUnity` for this MonoGame project.
- Choose one main ask: follow, give feedback, visit the game page, or wishlist. Use “Wishlist on Steam” only when the actual Steam page is live. Do not imply a demo is available unless it is publicly available.
- Replace `[GAME_URL]` with a real destination before publishing. Link-in-bio/profile examples assume that destination is already added and works. Without a game page, use a follow/feedback ask instead.

## Instagram

Put a short hook on the first line and hashtags at the end. “Link in bio” is a useful default because ordinary caption URLs generally are not clickable. Some Meta Verified creators have access to a caption-link test, so use that only if the account actually has it. [Caption-link rollout reporting](https://www.socialmediatoday.com/news/instagram-tests-links-in-post-captions-for-paying-users/814763/)

## YouTube Shorts

Use a descriptive title rather than the export filename. Put the game name and feature in the description, and add a small hashtag set at the end. YouTube supports hashtags in titles and descriptions; our default is to keep the title readable and put them in the description. [YouTube hashtag help](https://support.google.com/youtube/answer/10806146?hl=en)

**External URLs in Shorts descriptions and comments are not clickable.** Link the game from the channel profile and point there. A related-video link can direct viewers to another YouTube video when the feature is available; it is not a direct Steam link. [YouTube link guidance](https://support.google.com/youtube/answer/13748639?hl=en)

## Make shorts with the beyond-the-belt-shorts skill

[Skills/beyond-the-belt-shorts](Skills/beyond-the-belt-shorts/SKILL.md) makes a short end to end from new footage, for Claude Code and Codex alike:

1. **Stage** any game state in a scene file: a debug preset plus exact upgrade levels, currencies, stats, abilities, modules and signals.
2. **Record** it with the game's own capture mode (`--capture scene.json`). The game renders offscreen in a native 9:16 play field at 4K/60, on a fixed timestep, with scripted clicks, holds, gravity wells, abilities, upgrades and zooms. Every sound the game plays is logged, so the real game audio can be rebuilt.
3. **Edit** to music with `render_short.py`: punch-ins, slow pushes, slow motion, honest live numbers from the capture log, and text in the `fullscreen` layout (default) or the `banners` layout of Shorts 01-04.

Work folders live in `Marketing/Shorts/NN-slug/` (scenes and edit files are versioned; takes and renders are ignored by Git). The capture mode never uses the player's save or `Settings.json`, and only runs in development builds (`Demo.IsDev`).

### Install

The skill is linked, not copied, so edits in the repo apply immediately:

```bash
ln -sfn "$PWD/Marketing/Skills/beyond-the-belt-shorts" ~/.claude/skills/beyond-the-belt-shorts
ln -sfn "$PWD/Marketing/Skills/beyond-the-belt-shorts" "${CODEX_HOME:-$HOME/.codex}/skills/beyond-the-belt-shorts"
```

### Example prompts

```text
Make a 20-second short showing the graviton cascade chaining through a late-game swarm. Fullscreen layout, Sky Fish as music.
```

```text
Make a progression short: one ship clicking red gems, then the late-game fleet. Put the switch on the music drop and show the real gem counts.
```

```text
Make a short in the banners layout about the shipyard: equipping a module and the fleet using it.
```

### Run the tools directly

From the game directory:

```bash
S=Marketing/Skills/beyond-the-belt-shorts/scripts
python3 $S/capture.py --list Marketing/Shorts/catalog.json         # every preset, upgrade, stat, ability, module, signal
python3 $S/capture.py Marketing/Shorts/06-x/scenes/*.json --preview  # quick 540x960 takes and contact sheets
python3 $S/capture.py Marketing/Shorts/06-x/scenes/*.json            # 4K takes + game audio + sheets
python3 $S/render_short.py Marketing/Shorts/06-x/edit.json            # final MP4 + review sheet
```

### Recreate the original panel-based edits

Requires Linux, .NET 10, FFmpeg, an offscreen-capable SDL/OpenGL installation, and the already-built game with its native libraries and content in `bin/Debug/net10.0`. Run from the game directory:

```sh
python3 Marketing/Capture/capture.py
python3 Marketing/Capture/edit.py Marketing/Source
```

`capture.py --build /path/to/build` can select another compatible desktop build. Capture uses the compiled game, so build current source first if gameplay has changed. The capture harness creates temporary settings, saves, and working files; it does not use the developer's normal save. It waits for asset loading and eight seconds of gameplay before recording. Each recorded frame advances the simulation by 1/30 second, so slow offline rendering does not slow the final video. Random gameplay will vary between captures.

The `.cs.txt` file is intentionally a template so the main game's default C# file glob does not compile the capture entry point. Capture and editing tools are independent of the game's source. Raw footage and exports are ignored by Git to keep video binaries out of normal source commits.
